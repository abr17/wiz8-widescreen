# Wizardry 8 Widescreen 1.0.2 (2026-10-24)

Fixes for character creation, the party-death screen, a tooltip memory leak and Windows with
the UTF-8 system code page; a frame rate limit page (Options - Video, page 3; the default is
now 60); side wings made from the game's own marble; optional crash diagnostics; and a new
Options category for experimental features, off by default, with four switches: Animated Main
Menu, Map Mouse Controls, Original Bug Fixes and Alternative Game Tick.

## Changes

- Options - Experimental: a new category for features that are off by default and may change
  or be removed later. Its entry is a 5th button under the other four, "experimental" /
  "экспериментальные", and a USB drive drawn into the computer picture that lights up with it
  (the button pictures carry English or Russian labels, so with other game languages only the
  drive is there, as an unlabelled click area). The first switch: animated main menu, a looped
  15-second animation of the menu background (`Data\WIDE\MENU_ANIM.AVI`, 856x480, 15 frames
  per second, drawn by the patch; the menu items stay as in the original, only their baked-in
  background is left out). Switched in the game without a restart (applies the next time the
  main menu opens) or with `[Experimental] AnimatedMenu=1` in `wiz8wide.ini` (an update keeps
  the player's old `wiz8wide.ini`, which has no such section; the switch adds it). A damaged or
  missing video file leaves the original still picture. Art and animation made with generative AI.
  The second switch: Map Mouse Controls (`[Experimental] ModernMap=1`, applies at once). On
  the map (Tab) the mouse wheel zooms in small steps towards the pointer, dragging with the
  left button moves the map (hand cursor), a double click does what the original's single click
  did (zoom in at the pointer to the next of the original's levels), and a single
  click does nothing except on the party marker (there it is the original's click too); the
  right click, the note tools, the keys and the buttons work as in the original.

  The third switch: Original Bug Fixes (`[Experimental] OriginalFixes=1`, applies at once), the
  one place where the patch fixes the original game's own bugs. For now it fixes the silent
  crash after about 20 loads (entering, or loading a save) of Arnika Road from the starter
  dungeon, the Arnika - Trynton road, Trynton, Savant's tower or Ascension in one session: their
  region link files are empty, the original leaves each one open, and at the 20th open file the
  original's own open file list breaks. It also fixes the crash on exit when the game window is
  closed with Alt+F4 (or its X in window mode), and a small memory leak on every saved-game load
  (the radar and formation board pictures were never freed). Off, the game behaves exactly as the original.

  The fourth switch: Alternative Game Tick (`[Experimental] FrameRateFix=1`, applies at once).
  The party moves at any frame rate as the original does at 30 fps (the Umpani doorsteps and
  stairs are climbed as intended even at 144 fps or uncapped), while the picture stays as smooth
  as the frame rate. What ran faster or slower with the frame rate (monsters looking about and
  fidgeting, flickering lights, floating damage numbers, arrow-key map scrolling, mouse-look
  smoothing) behaves at any frame rate as the original does at 30 fps, music and ambient sound
  fades last the length the game asks for, and camera fly-bys and scrolling water move smoothly
  above 64 fps. Off, the game behaves exactly as the original.

- Character creation: a click on the Nickname field after typing the full name moves the
  cursor there at once. Since 1.0.0 it took many clicks: the game code compared text fields by
  their place in memory instead of by number, so a click on the second field was ignored while
  the first one was active (checked against the original's machine code at 0x5d50a2; the
  original switches with one click).
- Party death: when the whole party died, the game hung on a black 3D view with the HUD and the
  combat log, without the "Your party has been defeated!" picture, and no key or click got out.
  Since 1.0.0: the patch's own fade code kept "what to run when the fade ends" in a private copy
  that the game's code never read, so the defeat screen was never drawn nor left (the endings use
  the same fade). Now the defeat picture covers the whole screen and a key or a click returns to
  the main menu, as in the original (details: [wide-canvas.md](../wide-canvas.md)).
- Memory: every tooltip leaked about 128 KB since 1.0.0 (300 tooltips: about 45 MB). The
  patch's replaced `Video2DRectToPolygon` kept the tooltip picture's surface, which the
  original hands over to be freed with the picture (`autoRelease`), so it was never freed; the
  game has only 2 GB of address space. Fixed, always on: the bug was the patch's own, so it is
  not behind the Original Bug Fixes switch.
- Windows with the beta option "Use Unicode UTF-8 for worldwide language support": every
  new Russian nickname was refused as "a character with this nickname already exists", and
  Russian names of saves and characters showed as garbage. The game passes these names to
  Windows as single-byte text, which this option turns into "unknown character" marks, so all
  names of the same length became the same file (`����.CHR`). The bug is in the original game's
  code; it blocks the Russian translation on such systems, so the patch fixes it: on UTF-8
  Windows only, the game's file names are passed to Windows in the code page Windows uses
  without the option. Files are named as the game names them with the option off (one rare
  exception: names like "Рё" whose bytes are also valid UTF-8), older saves and characters keep
  working, file contents do not change (saves stay compatible with the original game).
  `[General] Utf8FileNames=0` in `wiz8ws.ini` turns it off. Details: [loader.md](../loader.md).
- Crash diagnostics, off by default: with `[Debug] Diagnostics=1` in `wiz8ws.ini` the patch
  records how the game ends (exit code, call stack, the game's own error text, memory), writes
  a minidump on a real crash (also after a stack overflow) and keeps the logs of the last 10
  sessions in `Wiz8Logs\`. A crash in the game's own code on its main thread, which Windows
  ends without running any crash handler, is written down when it happens (found on the silent
  Arnika Road crash). The installer has a "Diagnostics mode (for bug reports)" checkbox for it,
  off on a fresh install; over an install it shows the current value and keeps whatever the player
  leaves it at (without the window: `--diagnostics` / `--no-diagnostics`). The READMEs say how to
  turn it on and what to send. The installer keeps `Wiz8Logs\` on update (moving the last session's logs
  into it first) and removes it on a full uninstall.
- For developers: `build\test_filenames.exe` (CMake target `test_filenames`) tests the
  file-name layer without the game; the installer tests fake "the next version" instead of a
  fixed 1.0.2; the `wiz8hy.dll` build fails when a game variable would get a private copy in
  the DLL, the cause of the party-death hang ([hybrid.md](../hybrid.md), "Game variables").
- Save/load list: the empty rows (fewer than five saves on a page) were stretched by repeating
  a piece of the picture, with a brightness step on the top frame line and a repeating crack
  pattern; 1.0.1 made seamless strips for the other rows only. Now they have their own
  (`Data\WIDE\STRETCH\S0F9_0_4_768/856.STI`, made by `scripts\art\stretch_quilt.py`).
- Frame rate limit: the default is now 60 (was 120), and Options - Video has a third page with
  a slider (30 / 60 / 120) and an "Unlimited" checkbox. The 2001 engine moves the
  party a step per frame, so the higher the rate, the harder tall ledges and stairs are to
  climb (the Umpani camp doors needed a run-up; the original without a cap runs at ~220 fps on
  a modern PC and is worse still). 60 is what a good PC of 2001 gave. An update keeps the
  player's old `wiz8wide.ini`, so an old `MaxFps=120` stays until changed on the new page.
- The stone beside the windows that stay 4:3 (inventory and stats, character creation, party
  selection; options, journal and map when their wide layouts are off) is now made from the
  game's own marble instead of the AI-painted marble of 1.0.0/1.0.1: pieces of the original
  inventory, creation, map-frame and stats backgrounds stitched without visible seams, with
  the same dark groove at the window edge (`Data\WIDE\WIDEFRAME_768/856.STI`, made by
  `scripts\art\native_wings.py`).
- Logs: `wiz8hy.log` said "frame cap: off" although the frame cap works (in the replaced
  RenderFrame), and `wiz8wide.log` reported a missing strip for the journal parchment, which
  is drawn by mirroring and needs none. Both lines are corrected.
