# Wizardry 8 Widescreen 1.0.1 (2026-10-18)

Fixes after the first player reports on 1.0.0, and an installer that updates an installed 1.0.0
in place.

## Changes

- Full screen keeps the picture's proportions: the monitor stays in its own mode and the game
  is shown with black bars instead of being stretched (dgVoodoo `ScalingMode = stretched_ar`).
  The mouse reaches the whole picture and lands where it points: the patch maps the cursor
  into the picture between the bars, and dgVoodoo's `CaptureMouse` is off (it confined the
  cursor to the chosen resolution's size from the screen's top-left corner). Videos in full
  screen now play through the 2D canvas like in borderless mode: before, every video switched
  to 640x480, so the screen went black and the picture jumped to 4:3 and back.
- The combat progress bar at the top of the screen spans the whole wide screen, and it now
  behaves as in the original: it grows while the round's actions run and is gone while the
  party waits for orders. Since 1.0.0 it was the other way round, in every format (the game
  code tested the "round open" flag instead of the "actions running" one; checked against the
  original's machine code at 0x563365).
- New 16:9 art for the wide interface strips that looked repetitive (options and other
  panels, approved by the author); the 16:10 strips are now cut from the 16:9 ones, so both
  formats look the same.
- Options - Video opens without a pause: the list of screen modes is collected once in the
  background at start-up.
- Installer: shows its version; over an installed older version the button reads
  "Update 1.0.0 -> 1.0.1" (the old files are removed first, `wiz8wide.ini` is kept), over the
  same version "Reinstall", over a newer one "Roll back 1.0.2 -> 1.0.1" after a Yes/No question.
  The version is written into `Wiz8Wide.installed.txt` (first line `*version=1.0.1`; a list
  without it is 1.0.0). A future installer that changes what uninstall has to do will write
  `*format=2`; this one then leaves such a folder alone and names the installer to use. (The
  released 1.0.0 installer knows nothing of this: run over a newer install it silently puts
  1.0.0 back, which works correctly.) `wiz8ws.log` starts with the patch version.
- Installer safety (found while reviewing the update path; the same holes were in the 1.0.0
  reinstall): it refuses to change anything while the game (or another program) holds a file
  of the folder open, instead of half-removing the patch; the player's `wiz8wide.ini` and the
  `wiz8ws.ini` off switch (`Enabled=0`) survive an update, a rollback and even a failed copy;
  patch files left by a manual install are no longer saved as "originals"; an uninstall that
  cannot remove a file keeps the rest in the list so it can simply be run again.
- The main menu shows the patch version next to the game's: "v1.2.4 (Widescreen v1.0.1)".
- For developers: one `VERSION` file feeds the installer, `version.dll`, `wiz8hy.dll` (the
  main menu line, define `WIZ8WIDE_VERSION` from `build_hybrid.py`) and the package name;
  `scripts\build\import-release.ps1` fills `assets\` from a released zip.

## Tested

On a clean copy of the GOG game (the Steam exe is the same file): install 1.0.0 from its
released zip, change a setting and set `Enabled=0`, update with the 1.0.1 installer (button
"Update 1.0.0 -> 1.0.1", every package file installed, backups equal the originals, both
settings kept), start the game (wide 16:10 menu, 287 functions replaced, version in
`wiz8ws.log`); with the game running, Reinstall and Uninstall are refused and the folder stays
unchanged; reinstall 1.0.1, install 1.0.0 back over it and update again; roll back from a faked
1.0.2 (with an extra file, an extra folder and one more replaced original): "No" changes
nothing, "Yes" removes all of 1.0.2 and restores the original; a faked `*format=2` install:
both buttons off, command-line install/uninstall refused, folder unchanged; a copy forced to
fail in the middle of a reinstall: the folder is back to the original plus the player's
`wiz8wide.ini` and `Enabled=0`, and the next install keeps both; an install over a manual
install whose settings survive only as `wiz8wide.ini.keep` (the state a failed 1.0.0 reinstall
left): settings restored, no patch file saved as an original; an empty manifest counts as not
installed; uninstall by 1.0.1 and by the 1.0.0 installer (the folder matches the original byte
for byte). 38 checks, all passed: `tools_src\setup\tests\test_all.ps1`.
Full screen on a 2560x1600 monitor at 1920x1080 (bars top and bottom), 1600x1200 (bars left
and right) and 1920x1200 (no bars): the cursor reaches every corner of the picture, the game
draws it where the Windows cursor is, and a click on Options in the main menu opens Options;
the same in borderless and in a 1920x1080 window. Full screen 1920x1080: the Introduction video
from the main menu starts and ends without a black screen or a jump of the picture (it shows 4:3
in the middle of the 16:9 picture, as in borderless; the whole screen sampled every 0.2-0.3 s).
The README collages were re-shot with this
build (main menu with the version line, Options - Video, character sheet, exploring, the crab
fight at the end of round 1) at 16:10 borderless, 16:9 full screen and in the original game.
Combat progress bar: the same crab fight, two rounds, captured every 0.6 s in the original, in
the patch at 4:3 and at 16:10: the patch now matches the original (fill grows during the
round, empty while waiting for orders; before the fix it was the reverse). Earlier, on the same
game code: the new strips on the affected screens at 16:10 and 16:9.
